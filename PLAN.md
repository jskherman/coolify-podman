### Native Application integration decision — before enabling native resources

Use `RuntimeContext` as the native Application polymorphic destination, with explicit immutable runtime mode and separate native workload/release records. It already supplies `destination->server`; a fake Docker destination would allow accidental inherited execution. This decision is not yet implemented.

- Centralize all five direct `ApplicationDeploymentJob::dispatch` paths in `bootstrap/helpers/applications.php` behind runtime selection, and add a defensive constructor guard before numeric Docker destination lookup. Branch before any Docker network/helper-container setup.
- Native stop must branch in `StopApplication` before container discovery. Cancellation (`DeploymentNavbar`, `DeployController`), deletion (`DeleteResourceJob` and Application cleanup methods), logs (`ApplicationsController`, shared Logs/GetLogs) and rollback each need explicit typed handling.
